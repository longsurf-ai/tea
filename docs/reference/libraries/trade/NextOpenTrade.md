Coordinator whose orders fill at the next bar's open, or optionally at this bar's close.

```tea
type NextOpenTrade<B: broker.NextOpenBroker, P: portfolio.NetLedger>
```

| Field          | Description                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| `B broker`     | Broker that validates and fills this coordinator's orders.                                                   |
| `P portfolio`  | Portfolio that records this coordinator's fills.                                                             |
| `int idx = -1` | Bar index from the latest `begin_bar`, or `-1` before the first; later orders record it as `signalBarIndex`. |

Create it with [`trade.nextOpen`](./nextOpen.md). Each bar, call `begin_bar` before your
signal logic, submit orders, then call `end_bar`. Close fills need a broker
created with `processOrdersOnClose = true`. Use these methods rather than
calling `broker` or `portfolio` directly.

## Methods

### begin_bar

Starts a bar: fills the pending order at `openPrice` and applies the fill to the portfolio.

```tea
broker.Fill begin_bar(float openPrice, int barIndex)
```

| Parameter   | Type    | Description                           |
| ----------- | ------- | ------------------------------------- |
| `openPrice` | `float` | the bar's open                        |
| `barIndex`  | `int`   | the bar's index, normally `bar_index` |

**Returns:** the last fill applied, or `na` when nothing filled.

Call it once per bar, before your signal logic. Orders submitted later in the bar cannot fill at this open.

### entry

Submits an entry order that fills at the next open, or at this bar's close when close fills are enabled.

```tea
broker.Order entry(
    string commandId,
    trade.Direction direction,
    float qty = na,
    trade.Sizing sizing = na
)
```

| Parameter   | Type              | Default | Description                                                                                                                                  |
| ----------- | ----------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `commandId` | `string`          |         | name of the order; `cancel` takes it                                                                                                         |
| `direction` | `trade.Direction` |         | `trade.Direction.long` to buy or `trade.Direction.short` to sell                                                                             |
| `qty`       | `float`           | `na`    | quantity to open or add; must be positive                                                                                                    |
| `sizing`    | `trade.Sizing`    | `na`    | percent-of-equity sizing from [`trade.percentOfEquity`](./percentOfEquity.md) or [`trade.percentOfEquityAtFill`](./percentOfEquityAtFill.md) |

**Returns:** the accepted [`broker.Order`](../broker/Order.md), or `na` when the broker rejects it on submission, for example while another order is pending.

Pass at most one of `qty` and `sizing` (both together are rejected); with neither, the broker sizes the entry from all available capital. An entry against the open position reverses it: the broker closes the position, then opens the new one. Adding to a position requires the same `commandId` and room under the portfolio's `pyramiding`.

### close

Submits an order that closes the whole position at the next open, or at this bar's close when enabled.

```tea
broker.Order close(string commandId)
```

| Parameter   | Type     | Description                          |
| ----------- | -------- | ------------------------------------ |
| `commandId` | `string` | name of the order; `cancel` takes it |

**Returns:** the accepted order, or `na` when the broker rejects it on submission.

The broker rejects it if the position is flat when it would fill.

### rebalance

Submits an order that moves the position to `target` at the next open, or at this bar's close when enabled.

```tea
broker.Order rebalance(
    string commandId,
    broker.PositionTarget target
)
```

| Parameter   | Type                    | Description                                                                                                              |
| ----------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `commandId` | `string`                | name of the order; `cancel` takes it                                                                                     |
| `target`    | `broker.PositionTarget` | target from [`trade.targetQuantity`](./targetQuantity.md) or [`trade.targetPercentOfEquity`](./targetPercentOfEquity.md) |

**Returns:** the accepted order, or `na` when the broker rejects it on submission.

When it fills, the broker trades the difference between the target and the position, and cancels the order if there is none. Submitting again with the same `commandId` while it is pending replaces the target.

### cancel

Cancels the pending order named `commandId`.

```tea
int cancel(string commandId)
```

| Parameter   | Type     | Description                       |
| ----------- | -------- | --------------------------------- |
| `commandId` | `string` | name the order was submitted with |

**Returns:** the number of orders cancelled; `0` when none matched.

### process_close

Fills the pending order at `closePrice` when the broker processes orders on close, and applies the fill.

```tea
broker.Fill process_close(float closePrice)
```

| Parameter    | Type    | Description     |
| ------------ | ------- | --------------- |
| `closePrice` | `float` | the bar's close |

**Returns:** the last fill applied, or `na` when nothing filled.

Without `processOrdersOnClose = true` on the broker it fills nothing. Use it with `mark` and `finish` instead of `end_bar` to act between those steps; calling it again after submitting a new order fills that order at the same close. The reference broker makes at most two fills per bar.

### mark

Values the portfolio at `price`, updating equity, peak equity and drawdown.

```tea
float mark(float price)
```

| Parameter | Type    | Description                                      |
| --------- | ------- | ------------------------------------------------ |
| `price`   | `float` | price to value the position at, normally `close` |

**Returns:** the new equity.

### finish

On the last bar, expires every pending order without closing the position.

```tea
broker.FinishResult finish(bool isLast)
```

| Parameter | Type   | Description                              |
| --------- | ------ | ---------------------------------------- |
| `isLast`  | `bool` | whether this is the last bar of the data |

**Returns:** the expired orders as a [`broker.FinishResult`](../broker/FinishResult.md), or `na` when `isLast` is `false`.

Does nothing when `isLast` is `false`.

### end_bar

Ends the bar: runs `process_close`, `mark` and `finish` in that order.

```tea
broker.FinishResult end_bar(float closePrice, bool isLast)
```

| Parameter    | Type    | Description                              |
| ------------ | ------- | ---------------------------------------- |
| `closePrice` | `float` | the bar's close                          |
| `isLast`     | `bool`  | whether this is the last bar of the data |

**Returns:** the orders expired on the last bar, or `na` when `isLast` is `false`.

Tea has no builtin that marks the last bar, so pass `false` unless the script knows it, for example from an input.
