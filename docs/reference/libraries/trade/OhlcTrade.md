Coordinator that matches pending orders and one stop/target exit against each bar's high-low range.

```tea
type OhlcTrade<B: broker.OhlcBroker, P: portfolio.NetLedger>
```

| Field          | Description                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| `B broker`     | Broker that validates and fills this coordinator's orders.                                                   |
| `P portfolio`  | Portfolio that records this coordinator's fills.                                                             |
| `int idx = -1` | Bar index from the latest `begin_bar`, or `-1` before the first; later orders record it as `signalBarIndex`. |

Create it with [`trade.ohlc`](./ohlc.md). It does not assume whether the high or
the low came first and has no trailing exits; use [`trade.PathTrade`](./PathTrade.md)
when either matters. Each bar, call `begin_bar`, submit orders and exits,
then call `end_bar`. Use these methods rather than calling `broker` or
`portfolio` directly.

## Methods

### begin_bar

Starts a bar: fills the pending order, then the attached exit, against this bar's range.

```tea
broker.BarMatches begin_bar(
    float openPrice,
    float highPrice,
    float lowPrice,
    int barIndex
)
```

| Parameter   | Type    | Description                           |
| ----------- | ------- | ------------------------------------- |
| `openPrice` | `float` | the bar's open                        |
| `highPrice` | `float` | the bar's high                        |
| `lowPrice`  | `float` | the bar's low                         |
| `barIndex`  | `int`   | the bar's index, normally `bar_index` |

**Returns:** a [`broker.BarMatches`](../broker/BarMatches.md): `pending` holds the order's fill, `reversalClose` the closing fill when that order reversed the position, and `exit` the exit's fill; each is `na` when absent.

Market orders fill at the open. A stop entry or exit fills at the open when the bar gaps past its price, otherwise at that price. If the bar reaches both the exit's stop and target, the broker assumes the extreme nearer the open came first; a tie goes to the stop.

### entry

Submits a market or stop entry order; it fills in a later bar, or at this bar's close when enabled.

```tea
broker.Order entry(
    string commandId,
    trade.Direction direction,
    float qty = na,
    trade.Sizing sizing = na,
    float stop = na
)
```

| Parameter   | Type              | Default | Description                                                                                                                                  |
| ----------- | ----------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `commandId` | `string`          |         | name of the order; exits and `cancel` refer to it                                                                                            |
| `direction` | `trade.Direction` |         | `trade.Direction.long` to buy or `trade.Direction.short` to sell                                                                             |
| `qty`       | `float`           | `na`    | quantity to open or add; must be positive                                                                                                    |
| `sizing`    | `trade.Sizing`    | `na`    | percent-of-equity sizing from [`trade.percentOfEquity`](./percentOfEquity.md) or [`trade.percentOfEquityAtFill`](./percentOfEquityAtFill.md) |
| `stop`      | `float`           | `na`    | stop price that makes this a stop entry: a long triggers at or above it, a short at or below it                                              |

**Returns:** the accepted [`broker.Order`](../broker/Order.md), or `na` when the broker rejects it on submission, for example while another order is pending.

Pass at most one of `qty` and `sizing` (both together are rejected); with neither, the broker sizes the entry from all available capital. An entry against the open position reverses it: the broker closes the position, then opens the new one. Adding to a position requires the same `commandId` and room under the portfolio's `pyramiding`. Resubmitting a pending stop entry with the same `commandId` and a new `stop` replaces it.

### exit

Attaches a stop and/or target exit that closes the whole position opened by entry `fromEntry`.

```tea
broker.Order exit(
    string commandId,
    string fromEntry,
    float stop = na,
    float target = na,
    bool activateOnEntryBar = false
)
```

| Parameter            | Type     | Default | Description                                          |
| -------------------- | -------- | ------- | ---------------------------------------------------- |
| `commandId`          | `string` |         | name of the exit; `cancel` takes it                  |
| `fromEntry`          | `string` |         | `commandId` of the entry the exit belongs to         |
| `stop`               | `float`  | `na`    | stop price                                           |
| `target`             | `float`  | `na`    | target price                                         |
| `activateOnEntryBar` | `bool`   | `false` | whether the exit may fill on the bar its entry fills |

**Returns:** the accepted order, or `na` when the broker rejects it on submission.

Give `stop`, `target` or both; for a long the stop must be below the target, for a short above it. `fromEntry` must name the pending entry or the entry that opened the position. One exit is attached at a time: resubmitting the same `commandId` and `fromEntry` replaces it, and closing the position cancels it.

### close

Submits an order that closes the whole position at the next open, or at this bar's close when enabled.

```tea
broker.Order close(string commandId)
```

| Parameter   | Type     | Description                          |
| ----------- | -------- | ------------------------------------ |
| `commandId` | `string` | name of the order; `cancel` takes it |

**Returns:** the accepted order, or `na` when the broker rejects it on submission.

The broker rejects it if the position is flat when it would fill.

### rebalance

Submits an order that moves the position to `target` at the next open, or at this bar's close when enabled.

```tea
broker.Order rebalance(
    string commandId,
    broker.PositionTarget target
)
```

| Parameter   | Type                    | Description                                                                                                              |
| ----------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `commandId` | `string`                | name of the order; `cancel` takes it                                                                                     |
| `target`    | `broker.PositionTarget` | target from [`trade.targetQuantity`](./targetQuantity.md) or [`trade.targetPercentOfEquity`](./targetPercentOfEquity.md) |

**Returns:** the accepted order, or `na` when the broker rejects it on submission.

When it fills, the broker trades the difference between the target and the position, and cancels the order if there is none. Submitting again with the same `commandId` while it is pending replaces the target.

### cancel

Cancels the pending order or attached exit named `commandId`.

```tea
int cancel(string commandId)
```

| Parameter   | Type     | Description                       |
| ----------- | -------- | --------------------------------- |
| `commandId` | `string` | name the order was submitted with |

**Returns:** the number of orders cancelled; `0` when none matched.

Cancelling a pending entry also cancels an exit attached to it while no position is open.

### process_close

Fills the pending order at `closePrice` when the broker processes orders on close, and applies the fill.

```tea
broker.Fill process_close(float closePrice)
```

| Parameter    | Type    | Description     |
| ------------ | ------- | --------------- |
| `closePrice` | `float` | the bar's close |

**Returns:** the last fill applied, or `na` when nothing filled.

Without `processOrdersOnClose = true` on the broker it fills nothing, and it never triggers the attached exit. Use it with `mark` and `finish` instead of `end_bar` to act between those steps; calling it again after submitting a new order fills that order at the same close. The reference broker makes at most two fills per bar.

### mark

Values the portfolio at `price`, updating equity, peak equity and drawdown.

```tea
float mark(float price)
```

| Parameter | Type    | Description                                      |
| --------- | ------- | ------------------------------------------------ |
| `price`   | `float` | price to value the position at, normally `close` |

**Returns:** the new equity.

### finish

On the last bar, expires the pending order and attached exit without closing the position.

```tea
broker.FinishResult finish(bool isLast)
```

| Parameter | Type   | Description                              |
| --------- | ------ | ---------------------------------------- |
| `isLast`  | `bool` | whether this is the last bar of the data |

**Returns:** the expired orders as a [`broker.FinishResult`](../broker/FinishResult.md), or `na` when `isLast` is `false`.

Does nothing when `isLast` is `false`.

### end_bar

Ends the bar: runs `process_close`, `mark` and `finish` in that order.

```tea
broker.FinishResult end_bar(float closePrice, bool isLast)
```

| Parameter    | Type    | Description                              |
| ------------ | ------- | ---------------------------------------- |
| `closePrice` | `float` | the bar's close                          |
| `isLast`     | `bool`  | whether this is the last bar of the data |

**Returns:** the orders expired on the last bar, or `na` when `isLast` is `false`.

Tea has no builtin that marks the last bar, so pass `false` unless the script knows it, for example from an input.
