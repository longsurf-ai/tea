Coordinator that replays each bar as an ordered price path, with fixed and trailing exits.

```tea
type PathTrade<B: broker.PathBroker, P: portfolio.NetLedger>
```

| Field          | Description                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| `B broker`     | Broker that validates and fills this coordinator's orders.                                                   |
| `P portfolio`  | Portfolio that records this coordinator's fills.                                                             |
| `int idx = -1` | Bar index from the latest `begin_bar`, or `-1` before the first; later orders record it as `signalBarIndex`. |

Create it with [`trade.path`](./path.md). The path runs from the open to the
nearer of the high and low, then to the farther one, then to the close;
when both are equally far, the low comes first. When an order fills partway
along the path, its exit only sees the rest of the bar. Each bar, call
`begin_bar`, attach or adjust exits, call `continue_bar`, submit new orders,
then call `end_bar`. Use these methods rather than calling `broker` or
`portfolio` directly.

## Methods

### begin_bar

Starts a bar: fills the pending order along this bar's path and records where it filled.

```tea
broker.BarMatches begin_bar(
    float openPrice,
    float highPrice,
    float lowPrice,
    float closePrice,
    int barIndex
)
```

| Parameter    | Type    | Description                           |
| ------------ | ------- | ------------------------------------- |
| `openPrice`  | `float` | the bar's open                        |
| `highPrice`  | `float` | the bar's high                        |
| `lowPrice`   | `float` | the bar's low                         |
| `closePrice` | `float` | the bar's close                       |
| `barIndex`   | `int`   | the bar's index, normally `bar_index` |

**Returns:** a [`broker.BarMatches`](../broker/BarMatches.md): `pending` holds the order's fill and `reversalClose` the closing fill when that order reversed the position, each `na` when absent; `exit` is always `na`.

Market orders fill at the open; a stop entry fills at the open when the bar gaps past its stop, otherwise where the path crosses it. The attached exit is not checked here; `continue_bar` checks it on the rest of the path, so an exit derived from this fill can be attached first.

### continue_bar

Checks the attached exit, including its trailing stop, along the part of the bar after `begin_bar`'s fill.

```tea
broker.Fill continue_bar(
    float openPrice,
    float highPrice,
    float lowPrice,
    float closePrice
)
```

| Parameter    | Type    | Description     |
| ------------ | ------- | --------------- |
| `openPrice`  | `float` | the bar's open  |
| `highPrice`  | `float` | the bar's high  |
| `lowPrice`   | `float` | the bar's low   |
| `closePrice` | `float` | the bar's close |

**Returns:** the exit's fill, or `na` when the exit did not trigger.

Call it after `begin_bar` and any exit changes, with the same prices. When nothing filled in `begin_bar`, it checks the whole bar.

### entry

Submits a market or stop entry order that fills in a later bar.

```tea
broker.Order entry(
    string commandId,
    trade.Direction direction,
    float qty = na,
    trade.Sizing sizing = na,
    float stop = na
)
```

| Parameter   | Type              | Default | Description                                                                                                                                  |
| ----------- | ----------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `commandId` | `string`          |         | name of the order; exits and `cancel` refer to it                                                                                            |
| `direction` | `trade.Direction` |         | `trade.Direction.long` to buy or `trade.Direction.short` to sell                                                                             |
| `qty`       | `float`           | `na`    | quantity to open or add; must be positive                                                                                                    |
| `sizing`    | `trade.Sizing`    | `na`    | percent-of-equity sizing from [`trade.percentOfEquity`](./percentOfEquity.md) or [`trade.percentOfEquityAtFill`](./percentOfEquityAtFill.md) |
| `stop`      | `float`           | `na`    | stop price that makes this a stop entry: a long triggers at or above it, a short at or below it                                              |

**Returns:** the accepted [`broker.Order`](../broker/Order.md), or `na` when the broker rejects it on submission, for example while another order is pending.

Pass at most one of `qty` and `sizing` (both together are rejected); with neither, the broker sizes the entry from all available capital. An entry against the open position reverses it: the broker closes the position, then opens the new one. Adding to a position requires the same `commandId` and room under the portfolio's `pyramiding`. Resubmitting a pending stop entry with the same `commandId` and a new `stop` replaces it.

### exit

Attaches a fixed and/or trailing exit that closes the whole position opened by entry `fromEntry`.

```tea
broker.Order exit(
    string commandId,
    string fromEntry,
    float stop = na,
    float target = na,
    bool activateOnEntryBar = false,
    float trailPrice = na,
    float trailOffset = na
)
```

| Parameter            | Type     | Default | Description                                                                   |
| -------------------- | -------- | ------- | ----------------------------------------------------------------------------- |
| `commandId`          | `string` |         | name of the exit; `cancel` takes it                                           |
| `fromEntry`          | `string` |         | `commandId` of the entry the exit belongs to                                  |
| `stop`               | `float`  | `na`    | stop price                                                                    |
| `target`             | `float`  | `na`    | target price                                                                  |
| `activateOnEntryBar` | `bool`   | `false` | whether the exit may fill on the bar its entry fills                          |
| `trailPrice`         | `float`  | `na`    | price that activates the trailing stop                                        |
| `trailOffset`        | `float`  | `na`    | distance the trailing stop keeps from the best price reached since activation |

**Returns:** the accepted order, or `na` when the broker rejects it on submission.

Give any of `stop`, `target` and the trailing pair `trailPrice` with `trailOffset`; for a long the stop must be below the target, for a short above it. Once active, the trailing stop takes the place of `stop` whenever it is tighter. `fromEntry` must name the pending entry or the entry that opened the position. One exit is attached at a time: resubmitting the same `commandId` and `fromEntry` replaces it, and closing the position cancels it.

### close

Submits an order that closes the whole position at the next open.

```tea
broker.Order close(string commandId)
```

| Parameter   | Type     | Description                          |
| ----------- | -------- | ------------------------------------ |
| `commandId` | `string` | name of the order; `cancel` takes it |

**Returns:** the accepted order, or `na` when the broker rejects it on submission.

The broker rejects it if the position is flat when it would fill.

### rebalance

Submits an order that moves the position to `target` at the next open.

```tea
broker.Order rebalance(
    string commandId,
    broker.PositionTarget target
)
```

| Parameter   | Type                    | Description                                                                                                              |
| ----------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `commandId` | `string`                | name of the order; `cancel` takes it                                                                                     |
| `target`    | `broker.PositionTarget` | target from [`trade.targetQuantity`](./targetQuantity.md) or [`trade.targetPercentOfEquity`](./targetPercentOfEquity.md) |

**Returns:** the accepted order, or `na` when the broker rejects it on submission.

When it fills, the broker trades the difference between the target and the position, and cancels the order if there is none. Submitting again with the same `commandId` while it is pending replaces the target.

### cancel

Cancels the pending order or attached exit named `commandId`.

```tea
int cancel(string commandId)
```

| Parameter   | Type     | Description                       |
| ----------- | -------- | --------------------------------- |
| `commandId` | `string` | name the order was submitted with |

**Returns:** the number of orders cancelled; `0` when none matched.

Cancelling a pending entry also cancels an exit attached to it while no position is open.

### end_bar

Ends the bar: marks the portfolio at `closePrice` and, on the last bar, expires pending orders.

```tea
broker.FinishResult end_bar(float closePrice, bool isLast)
```

| Parameter    | Type    | Description                              |
| ------------ | ------- | ---------------------------------------- |
| `closePrice` | `float` | the bar's close                          |
| `isLast`     | `bool`  | whether this is the last bar of the data |

**Returns:** the orders expired on the last bar as a [`broker.FinishResult`](../broker/FinishResult.md), or `na` when `isLast` is `false`.

This family never fills orders at the close. Tea has no builtin that marks the last bar, so pass `false` unless the script knows it, for example from an input.
