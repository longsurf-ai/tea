Order and fill types, and a deterministic broker emulator that fills strategy orders against bar prices.

A broker turns strategy commands into orders, decides whether, when and at
what price each order fills, applies commission and slippage, and reports
each step as an event. The portfolio library applies fills to cash and
positions, and a trade coordinator sequences broker and portfolio on every
bar. A strategy imports all three, creates a broker with [`broker.new`](./broker.md#new)
or [`broker.basic`](./broker.md#basic), and hands it with a portfolio to a coordinator such
as [`trade.nextOpen`](./trade.md#nextopen); it then trades through the coordinator rather
than calling the broker. See the [strategy model](../../strategy.md) for the full
responsibility boundary and the
[backtest guide](../../getting-started/backtest-your-strategy.md) for a runnable
walkthrough.

The library keeps no global state: each broker value holds its own orders,
ids and matching state. Broker events are appended to one output per event
type, such as `broker.FillExecuted`; each output keeps execution order, but
separate outputs share no ordering.

```tea
import broker
import portfolio
import trade

fast = ta.ema(close, 10)
slow = ta.ema(close, 30)

var strat = trade.nextOpen(
    broker.new(commission = broker.commissionRate(0.001)),
    portfolio.new(initialCash = 10000.0)
)

strat.begin_bar(open, bar_index)
if ta.crossover(fast, slow)
    strat.entry("Long", trade.Direction.long)
if ta.crossunder(fast, slow)
    strat.close("Long")
strat.end_bar(close, false)

metrics = strat.snapshot()
plot("equity", metrics.equity, "equity")
```

## Commission and slippage

### commissionRate

Commission charged as a fraction of each fill's notional.

```tea
broker.commissionRate(float rate = 0.0)
```

| Parameter | Type    | Default | Description                          |
| --------- | ------- | ------- | ------------------------------------ |
| `rate`    | `float` | `0.0`   | commission as a fraction of notional |

**Returns:** a `rate` [`broker.Commission`](./broker.md#commission).

`0.001` charges 0.1%. A negative or `na` rate makes the broker reject every
fill with `invalidConfiguration`.

### commissionPercent

Commission charged as a percent of each fill's notional.

```tea
broker.commissionPercent(float percent = 0.0)
```

| Parameter | Type    | Default | Description                         |
| --------- | ------- | ------- | ----------------------------------- |
| `percent` | `float` | `0.0`   | commission as a percent of notional |

**Returns:** a `rate` [`broker.Commission`](./broker.md#commission) holding `percent / 100`.

`0.1` charges 0.1%; the same as `commissionRate(percent / 100)`.

### commissionCashPerContract

Commission charged as fixed cash per unit of filled quantity.

```tea

```

| Parameter | Type    | Default | Description   |
| --------- | ------- | ------- | ------------- |
| `cash`    | `float` | `0.0`   | cash per unit |

**Returns:** a `cashPerContract` [`broker.Commission`](./broker.md#commission).

### commissionCashPerOrder

Commission charged as fixed cash per order.

```tea
broker.commissionCashPerOrder(float cash = 0.0)
```

| Parameter | Type    | Default | Description    |
| --------- | ------- | ------- | -------------- |
| `cash`    | `float` | `0.0`   | cash per order |

**Returns:** a `cashPerOrder` [`broker.Commission`](./broker.md#commission).

A reversal's closing and opening fills belong to one order and pay it once.

### slippageRate

Adverse slippage as a fraction of the matched price.

```tea
broker.slippageRate(float rate = 0.0)
```

| Parameter | Type    | Default | Description                     |
| --------- | ------- | ------- | ------------------------------- |
| `rate`    | `float` | `0.0`   | slippage as a fraction of price |

**Returns:** a `rate` [`broker.Slippage`](./broker.md#slippage).

`0.001` fills buys 0.1% above and sells 0.1% below the matched price. The
rate must be at least `0` and below `1`; otherwise the broker rejects every
fill with `invalidConfiguration`.

### slippagePercent

Adverse slippage as a percent of the matched price.

```tea
broker.slippagePercent(float percent = 0.0)
```

| Parameter | Type    | Default | Description                    |
| --------- | ------- | ------- | ------------------------------ |
| `percent` | `float` | `0.0`   | slippage as a percent of price |

**Returns:** a `rate` [`broker.Slippage`](./broker.md#slippage) holding `percent / 100`.

`0.1` moves each fill 0.1% against the order; the same as
`slippageRate(percent / 100)`.

### slippageTicks

Adverse slippage as a number of price ticks.

```tea
broker.slippageTicks(float ticks = 0.0, float tickSize = 0.0)
```

| Parameter  | Type    | Default | Description              |
| ---------- | ------- | ------- | ------------------------ |
| `ticks`    | `float` | `0.0`   | number of ticks per fill |
| `tickSize` | `float` | `0.0`   | price size of one tick   |

**Returns:** a `ticks` [`broker.Slippage`](./broker.md#slippage).

Buys fill `ticks * tickSize` above the matched price and sells the same
distance below. Neither may be negative, and `tickSize` must be positive
whenever `ticks` is not zero; otherwise the broker rejects every fill with
`invalidConfiguration`.

```tea
import broker
import portfolio
import trade

// Two ticks of 0.25 against every fill, plus 2.5 per contract.
var strat = trade.nextOpen(
    broker.new(
        commission = broker.commissionCashPerContract(2.5),
        slippage = broker.slippageTicks(2.0, 0.25)
    ),
    portfolio.new(initialCash = 50000.0)
)
```

## Creating brokers

### new

Creates a broker emulator with the given commission, slippage and close-processing settings.

```tea
broker.new(
    Commission commission = Commission.new(CommissionKind.rate, 0.0),
    Slippage slippage = Slippage.new(SlippageKind.rate, 0.0, 0.0),
    bool processOrdersOnClose = false,
)
```

| Parameter              | Type         | Default                                     | Description                                                                                        |
| ---------------------- | ------------ | ------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `commission`           | `Commission` | `Commission.new(CommissionKind.rate, 0.0)`  | commission setting from a helper such as [`broker.commissionRate`](./broker.md#commissionrate)     |
| `slippage`             | `Slippage`   | `Slippage.new(SlippageKind.rate, 0.0, 0.0)` | adverse slippage setting from a helper such as [`broker.slippageTicks`](./broker.md#slippageticks) |
| `processOrdersOnClose` | `bool`       | `false`                                     | whether pending commands may also fill at bar closes                                               |

**Returns:** a new [`broker.BrokerEmulator`](./broker.md#brokeremulator).

With the defaults it charges no commission or slippage. With
`processOrdersOnClose = true`, the next-open and OHLC coordinators also fill
pending commands at bar closes, including the close of the bar a command was
issued on. Pass the result to a trade coordinator such as
[`trade.nextOpen`](./trade.md#nextopen).

```tea
import broker
import portfolio
import trade

var strat = trade.ohlc(
    broker.new(
        commission = broker.commissionPercent(0.05),
        slippage = broker.slippageTicks(1.0, 0.01),
        processOrdersOnClose = true
    ),
    portfolio.new(initialCash = 10000.0)
)

average = ta.sma(close, 20)
strat.begin_bar(open, high, low, bar_index)
if ta.crossover(close, average)
    // Fills at this bar's close because processOrdersOnClose is true.
    strat.entry("Long", trade.Direction.long, qty = 10.0)
strat.end_bar(close, false)
```

### basic

Creates a broker emulator from an adverse slippage rate and a commission rate.

```tea
broker.basic(float adverseSlippageRate = 0.0, float takerFeeRate = 0.0)
```

| Parameter             | Type    | Default | Description                                                                                       |
| --------------------- | ------- | ------- | ------------------------------------------------------------------------------------------------- |
| `adverseSlippageRate` | `float` | `0.0`   | slippage as a fraction of price, as in [`broker.slippageRate`](./broker.md#slippagerate)          |
| `takerFeeRate`        | `float` | `0.0`   | commission as a fraction of notional, as in [`broker.commissionRate`](./broker.md#commissionrate) |

**Returns:** a new [`broker.BrokerEmulator`](./broker.md#brokeremulator) without close processing.

The same as [`broker.new`](./broker.md#new) with
`commission = broker.commissionRate(takerFeeRate)`,
`slippage = broker.slippageRate(adverseSlippageRate)` and
`processOrdersOnClose = false`. Note the argument order: slippage first,
then the fee.

```tea
import broker
import portfolio
import trade

// 0.05% adverse slippage, then a 0.1% commission.
var strat = trade.nextOpen(broker.basic(0.0005, 0.001), portfolio.new())
```

## Orders and fills

### Side

Side of an order or fill.

```tea
enum Side
```

| Member | Description                                                                 |
| ------ | --------------------------------------------------------------------------- |
| `buy`  | Increases the signed position: opens or adds to a long, or reduces a short. |
| `sell` | Decreases the signed position: opens or adds to a short, or reduces a long. |

### CommandKind

What a command asks the broker to do.

```tea
enum CommandKind
```

| Member      | Description                                                                                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entry`     | Opens or adds to a position on the command's side; a scheduled entry against an open opposite position first closes it, then opens the new side (a reversal). |
| `close`     | Closes the whole position, or with immediate execution, the lot named by `tradeId`.                                                                           |
| `exit`      | Stop, target or trailing exit attached to an entry; it closes the whole position.                                                                             |
| `rebalance` | Moves the net position to a [`broker.PositionTarget`](./broker.md#positiontarget).                                                                            |

### OrderType

How an order is matched; on a fill, which kind of price it matched.

```tea
enum OrderType
```

| Member    | Description                                                                                                                                                                |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `market`  | No trigger price: fills at the next eligible open or close.                                                                                                                |
| `stop`    | Entry that triggers when price reaches its `stop` (rising for a buy, falling for a sell), or an exit with only a stop or trailing stop; on an exit fill, the stop matched. |
| `target`  | Exit with only a take-profit `target`; on an exit fill, the target matched.                                                                                                |
| `bracket` | Exit with a `target` plus a stop or trailing stop; its fill reports `stop` or `target`.                                                                                    |

### PositionTargetKind

Unit of a rebalance target; see [`broker.PositionTarget`](./broker.md#positiontarget).

```tea
enum PositionTargetKind
```

| Member            | Description                                                                           |
| ----------------- | ------------------------------------------------------------------------------------- |
| `quantity`        | Signed quantity: positive long, negative short, `0` flat.                             |
| `percentOfEquity` | Signed percent of equity, from `-100` to `100`, valued at the fill's reference price. |

### PositionTarget

Target position for a rebalance, made by [`trade.targetQuantity`](./trade.md#targetquantity) or [`trade.targetPercentOfEquity`](./trade.md#targetpercentofequity).

```tea
type PositionTarget
```

| Member                    | Description                                                             |
| ------------------------- | ----------------------------------------------------------------------- |
| `PositionTargetKind kind` | Unit of `value`.                                                        |
| `float value`             | Signed target: a quantity, or a percent of equity from `-100` to `100`. |

A rebalance fills the difference between the target and the current
position. With long margin enabled, a buy from a flat or long position is
limited to what the buying power pays for, so the position can stop short of
the target. A difference below `0.0000001` cancels the order instead.

### Account

Read-only view of the portfolio that the broker uses to validate and size fills.

```tea
type Account
```

| Member                           | Description                                                                                                       |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `float buyingPower`              | Cash the account can spend; equity is this plus the position valued at the reference price.                       |
| `float positionQuantity`         | Signed net position: positive long, negative short, `0` flat.                                                     |
| `int openEntryCount`             | Number of open entries counted against `pyramiding`.                                                              |
| `int pyramiding`                 | Maximum number of open entries; adding an entry needs `openEntryCount` below it.                                  |
| `float marginLong`               | Capital required for long exposure, as a percent of notional; `0` skips the capital check.                        |
| `float marginShort`              | Capital required for short exposure, as a percent of notional; `0` skips the capital check.                       |
| `bool configurationValid = true` | `false` when the portfolio's own settings are invalid; the broker then rejects fills with `invalidConfiguration`. |

The trade coordinator asks the portfolio for a fresh one before every broker
call that can fill, so broker matching never depends on how the portfolio
keeps its books. Strategies do not construct it.

### Command

One instruction from a strategy to the broker, built by the trade coordinators from calls such as `entry` and `exit`.

```tea
type Command
```

| Member                               | Description                                                                                                                                          |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `string commandId`                   | Strategy-chosen id; it names the order for replacement and cancellation, and an entry for `fromEntry`.                                               |
| `CommandKind kind`                   | What the command asks for.                                                                                                                           |
| `Side side`                          | Side of an entry or close; an exit takes the side that closes its entry, and a rebalance fills on the side that moves toward its target.             |
| `float quantity`                     | Explicit size in units, or `na`; a scheduled close ignores it and closes the whole position.                                                         |
| `int signalBarIndex`                 | Bar index where the command was issued; a scheduled command fills only on a later bar, or from this bar's close on when close processing is enabled. |
| `float notional = na`                | Size as cash value; the quantity is `notional` divided by the execution price.                                                                       |
| `string fromEntry = na`              | For an exit, the `commandId` of the entry it protects.                                                                                               |
| `float stop = na`                    | For an entry, the stop price that triggers it; for an exit, the stop-loss price.                                                                     |
| `bool activateOnEntryBar = false`    | For an exit, whether it may trigger on the bar its entry fills; otherwise it starts on the next bar.                                                 |
| `float target = na`                  | For an exit, the take-profit price.                                                                                                                  |
| `float cashBudget = na`              | For an entry, cash to spend including commission: notional plus commission equals this budget.                                                       |
| `float equityPercent = na`           | For an entry, size as a percent of equity at the fill's reference price, above `0` and at most `100`.                                                |
| `bool commissionIncluded = false`    | With `equityPercent`, whether commission comes out of the budget instead of on top of it.                                                            |
| `PositionTarget positionTarget = na` | For a rebalance, the target position.                                                                                                                |
| `float trailPrice = na`              | For an exit, the price at which the trailing stop activates.                                                                                         |
| `float trailOffset = na`             | For an exit, the price distance the trailing stop keeps behind the best price since activation.                                                      |
| `int tradeId = 0`                    | For an immediate close, the stable id of the lot to close; `0` otherwise.                                                                            |

The broker validates it when it is submitted or executed, and turns it into
an [`broker.Order`](./broker.md#order). Which fields apply depends on `kind`; the rest keep
their defaults, and prices are absolute levels. An entry uses at most one of
`quantity`, `notional`, `cashBudget` and `equityPercent`; with none set, a
scheduled entry spends all available capital, cash for a buy and equity for
a sell.

### Fill

One execution: what filled, when, at what price and for what fee.

```tea
type Fill
```

| Member                                        | Description                                                                                                                                        |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `int id`                                      | Broker-assigned id, counting up from `1` in each broker.                                                                                           |
| `int orderId`                                 | Id of the order that filled; both fills of a reversal share it.                                                                                    |
| `string commandId`                            | Command id of that order.                                                                                                                          |
| `Side side`                                   | Side of this fill.                                                                                                                                 |
| `int barIndex`                                | Bar index of the fill.                                                                                                                             |

| `float price`                                 | Execution price after adverse slippage.                                                                                                            |
| `float quantity`                              | Filled quantity, always positive.                                                                                                                  |
| `float notional`                              | `quantity * price`.                                                                                                                                |
| `float fee`                                   | Commission charged on this fill.                                                                                                                   |
| `OrderType orderType = OrderType.market`      | How it matched: the order's own type for an entry, close or rebalance, and `stop` or `target` for an exit; immediate fills always report `market`. |
| `CommandKind commandKind = CommandKind.entry` | What the fill did; the closing fill of a reversal reports `close`.                                                                                 |
| `int tradeId = 0`                             | Stable lot id for an immediate fill; `0` for a scheduled fill.                                                                                     |

The portfolio applies fills to its books, and the coordinators return them
to the strategy. `referencePrice` is the matched price; `price` adds adverse
slippage to it.

Returns: the fill, or `na`.                                                                                                                                                                                                   |

It keeps a deliberately small order model: one pending command (a market or
stop entry, a close, or a rebalance) and one attached exit (stop, target,
bracket or trailing stop). It is not a general order book, and a target is
not a true limit order: adverse slippage still applies after it matches. The
scheduled methods make at most two fills per bar; an order beyond that
waits, and a reversal's opening fill moves to the next open.

All of its state lives in its fields, so a script can run several
independent brokers. The trade coordinators call its methods in a fixed
order on every bar, and strategies use the coordinator instead. The
[strategy model](../../strategy.md) describes each coordinator's matching rules.
