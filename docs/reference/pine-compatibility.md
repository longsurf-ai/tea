Tea follows Pine Script v6: a name both have behaves the same way unless this page lists it. A Pine name missing from the [A–Z index](./a-z.md) is not in Tea yet. Some differences are in the language itself:

- A collection is a value: assigning it or passing it to a function copies it, where Pine Script shares a reference (see [memory model](../memory-model.md)).
- A request has no `lookahead` or `gaps` argument and never waits for a requested bar to close: each bar sees the newest requested bar that opened at or before it, so with completed daily data an intraday bar sees that day’s close (see [Request synchronization](../requests.md)).
- A function called under a condition keeps its history only on the bars where it runs (see [values and control flow](../language-guide/values-and-control-flow.md)).
- A function name is declared once: Tea has no overloading by parameter types or count, so a Pine library that overloads a name needs one untyped function or separate names (see [declarations](./language/declarations.md#functions)).

## Libraries

### ta

These differences apply across `ta`:

- Not in Tea yet: `ta.median`, `ta.mode`,
  `ta.percentile_linear_interpolation`, `ta.percentile_nearest_rank`,
  `ta.pivot_point_levels`, `ta.rci`, `ta.valuewhen`, `ta.vwap` (the function
  and the variable) and the variable `ta.tr`, which Tea writes as the call
  `ta.tr(false)`.
- The Pine manual states no minimum for counts such as `length`; in Tea a
  count below its minimum, such as a `length` of `0`, or an `na` count is an
  error.
- The Pine manual says that `na` values are ignored, and for some functions
  that the calculation uses `length` values that are not `na`. A Tea window
  function reads the last `length` bars and leaves out the `na` values among
  them, so it can use fewer than `length` values.

### visual

Every plot and alert function takes an output `id` first, so Pine
Script's `plot(ta.sma(close, 2))` fails with "missing argument 'series' in
call to 'plot'"; write `plot("sma", ta.sma(close, 2))`. Tea cannot create
drawing objects: there is no `label.new`, `line.new`, `box.new`,
`table.new`, `polyline.new` or `linefill.new`, so every value of the
`label`, `line`, `box`, `table`, `polyline` and `linefill` types is `na`.

## Parameters not supported yet

Tea accepts these Pine Script parameters by position but rejects any argument for them.

| Function                                             | Parameters   |
| ---------------------------------------------------- | ------------ |
| [`indicator`](./builtins/core.md#indicator)          | `shorttitle` |
| [`request.security`](./builtins/request.md#security) | `currency`   |

## Functions and values

| Name                                             | In Tea                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`plot`](./builtins/plots.md#plot)               | Tea has no `join`, `force_overlay` or `linestyle` parameter; passing one is an error. In Pine Script, `precision = 0` shows no decimal places; in Tea, `0` is the default and leaves the choice to the host.                                                                                                                                    |
| [`alert`](./builtins/alerts.md#alert)            | Pine Script's `alert(message, freq)` has a different signature: it takes no `id`, condition, title or payload, and Tea has no `freq` parameter or `alert.freq_*` constants.                                                                                                                                                                     |
| [`ta.vwma`](./builtins/ta/vwma.md)               | Pine's manual defines it as `ta.sma(source * volume, length) / ta.sma(volume, length)`. The two differ when `source` is `na` on a bar whose volume is known: Tea leaves that volume out, while `ta.sma(volume, length)` still counts it.                                                                                                        |
| [`ta.change`](./builtins/ta/change.md)           | Pine also accepts a `bool` source, returning `true` when it differs from the previous one; in Tea a `bool` source is a compile error.                                                                                                                                                                                                           |
| [`ta.stoch`](./builtins/ta/stoch.md)             | Pine names the second and third parameters `high` and `low`; Tea names them `h` and `l`, so named arguments read `h = high, l = low`.                                                                                                                                                                                                           |
| [`ta.range`](./builtins/ta/range.md)             | Pine's manual gives an `int` result for an `int` source; Tea's result is always `float`.                                                                                                                                                                                                                                                        |
| [`ta.supertrend`](./builtins/ta/supertrend.md)   | Pine's manual gives `direction` as `float`; Tea returns it as an `int`.                                                                                                                                                                                                                                                                         |
| [`ta.sar`](./builtins/ta/sar.md)                 | The reference code in Pine's manual starts the trend on the bar where `bar_index` is `1` and does not skip bars with a missing price. Tea starts on the second bar on which the call runs with a known high, low and close, and skips the bars without them; when every price is known and the call runs on every bar, the levels are the same. |
| [`ta.highest`](./builtins/ta/highest.md)         | Pine also has a one-argument form, `ta.highest(length)`, that searches `high`. Tea always takes `source`.                                                                                                                                                                                                                                       |
| [`ta.lowest`](./builtins/ta/lowest.md)           | Pine also has a one-argument form, `ta.lowest(length)`, that searches `low`. Tea always takes `source`.                                                                                                                                                                                                                                         |
| [`ta.highestbars`](./builtins/ta/highestbars.md) | Pine also has a one-argument form, `ta.highestbars(length)`, that searches `high`. Tea always takes `source`.                                                                                                                                                                                                                                   |
| [`ta.lowestbars`](./builtins/ta/lowestbars.md)   | Pine also has a one-argument form, `ta.lowestbars(length)`, that searches `low`. Tea always takes `source`.                                                                                                                                                                                                                                     |
| [`ta.pivothigh`](./builtins/ta/pivothigh.md)     | Pine also has a two-argument form without `source`, `ta.pivothigh(leftbars, rightbars)`; Tea always takes `source`. `leftbars` and `rightbars` must be `int`, where Pine also accepts a `float`.                                                                                                                                                |
| [`ta.pivotlow`](./builtins/ta/pivotlow.md)       | Pine also has a two-argument form without `source`, `ta.pivotlow(leftbars, rightbars)`; Tea always takes `source`. `leftbars` and `rightbars` must be `int`, where Pine also accepts a `float`.                                                                                                                                                 |
| [`str.tostring`](./builtins/core.md#tostring)    | Tea has no `format` argument and does not convert arrays.                                                                                                                                                                                                                                                                                       |
| [`runtime.error`](./builtins/core.md#error)      | A call that runs every time its script or function runs is rejected when the script compiles, instead of stopping the run.                                                                                                                                                                                                                      |
