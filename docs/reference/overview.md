The reference documents every name a Tea script can use, the language itself, the `tea` command and the JavaScript API. Each entry gives its syntax, parameters and result, and where they help, a formula, an example with its real output, and how it differs from Pine Script. To learn Tea, start with the Documentation tab.

## Reading signatures

A built-in reads `result name(qualifier type parameter, …)`. The result’s qualifier is shown only when it is fixed, as in `input int input.int(…)`; otherwise the result is as variable as the most variable argument. `= …` marks an optional parameter, whose description says what leaving it out means, and `...` marks one that takes any number of arguments. `int | float` accepts either type. Qualifiers go from least to most variable: `const`, `input`, `simple`, `series` (see [Types and qualifiers](./language/types.md)).

A function written in Tea, such as `ta.sma` or `trade.nextOpen`, shows its declaration as written: a parameter without a qualifier accepts any qualifier, a parameter without a type accepts any argument the function body can use, and **Returns** names the result type. Methods show their declarations, including the result type.

## Reading formulas

A formula names each value after the parameter it comes from, and a subscript names the bar. The current bar is t, so a value on the current bar and one i bars back read

$$
x_t = \texttt{x} \qquad x_{t-i} = \texttt{x[i]}
$$

A value before the first bar is `na`. Each entry’s **Warm-up and na** says when its result is `na`.

## How examples run

Every example on these pages is a complete program, and the output under it is what the program writes when the reference is built. The program runs as

```bash
tea run example.tea --input example.csv
```

on the CSV shown with it, or on a single bar whose `time` is 0 when it shows none. The CSV holds only the columns the program reads, and an empty cell is `na`. Each output column is a value the program writes with `emit`, and `index` counts bars from 0. A strategy’s run also writes the broker’s event outputs, such as `broker.FillExecuted`; the examples show only the columns they write themselves.

Examples are illustrations: they show what this version of Tea computes, not values checked against Pine Script.
