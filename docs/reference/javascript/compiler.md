The Tea compiler, for hosts that compile without the [`tea`](./tea.md#tea) template. Start with [`compileToProgram`](./compiler.md#compiletoprogram), which turns source files or in-memory text into the `Program` that [`generate`](./codegen-codegen.md#generate) lowers; [`compile`](./compiler.md#compile) runs the whole `tea build` path for files on disk, and [`compileForTooling`](./compiler.md#compilefortooling) keeps every stage's result for editors. Source diagnostics are never thrown: they collect in the [`Errors`](./base-print.md#errors) instance the caller passes, or in the result of [`compile`](./compiler.md#compile).

## Functions

### compile

Compile Tea files on disk to the TypeScript module source that `tea build` writes.

```ts
function compile(filenames: readonly string[]): CompileResult;
```

It runs [`compileToProgram`](./compiler.md#compiletoprogram) with its own [`Errors`](./base-print.md#errors), lowers the
Program with [`generate`](./codegen-codegen.md#generate), and type-checks the result against the
installed `tea/runtime` declarations.

Source diagnostics come back as `{ok: false, errors}`, sorted by position
and deduplicated, and stop compilation at the first failed stage. An
unreadable entry file throws its file-system error. A generated module that
fails the type check throws [`InternalError`](./base-print.md#internalerror): the frontend accepted
the program, so the failure is a compiler defect.

```ts
import { writeFileSync } from "node:fs";
import { compile } from "tea/compiler";

const result = compile(["rsi.tea"]);
if (result.ok) {
  writeFileSync("rsi.ts", result.source);
} else {
  for (const { pos, msg } of result.errors) {
    console.error(`${pos.base.filename}:${pos.line}:${pos.col}: ${msg}`);
  }
}
```

### compileForTooling

The tooling entry: the same stages as [`compileToProgram`](./compiler.md#compiletoprogram) without the barrier after parsing, so a file that is broken on one line still yields types, scopes and check errors for its other lines. The checker tolerates the `BadExpr` and `BadStmt` nodes of a recovered parse. Noding keeps its barrier and runs only when parse and check reported nothing.

```ts
function compileForTooling(
  inputs: readonly SourceInput[],
  errors: Errors,
): Compilation;
```

It is for editors and analysis only. Nothing that executes Tea may call it:
every backend consumes the `Program` of `compileToProgram`. `SourceInput.imports`
has the same contract as there.

User errors queue in `errors`; an `InternalError` thrown from here is a
compiler defect.

```ts
const errors = new Errors();
const { files, checked } = compileForTooling(
  [{ filename: "rsi.tea", source: 'x = 1 +\ny = close + "a"\n' }],
  errors,
);
errors.flushErrors(); // the parse error on line 1 and the type error on line 2
```

### compileToProgram

Compile inputs through the existing parse/check/node pipeline. Errors are recorded in `errors`; a failed stage returns null without running later stages. `includeSources` additionally returns the exact entry/import texts used by this compilation, excluding shipped libraries. Ordinary calls return Program.

```ts
function compileToProgram(
  inputs: readonly SourceInput[],
  errors: Errors,
  options: CompileOptions & {
    readonly includeSources: true;
  },
): ProgramWithSources | null;
function compileToProgram(
  inputs: readonly SourceInput[],
  errors: Errors,
  options?: CompileOptions & {
    readonly includeSources?: false;
  },
): Program | null;
function compileToProgram(
  inputs: readonly SourceInput[],
  errors: Errors,
  options: CompileOptions,
): Program | ProgramWithSources | null;
```

```ts
compileToProgram([{ filename: "main.tea", source, imports }], errors);
```

```ts
compileToProgram(["main.tea"], errors, { includeSources: true });
```

## Interfaces

### Compilation

One run of the frontend with every stage's result kept: what tooling reads instead of the `Program` alone. The run's errors are in the `Errors` the caller passed.

```ts
interface Compilation {
  readonly files: readonly File[];
  readonly dependencies: readonly string[];
  readonly checked: CheckedPackage;
  readonly program: Program | null;
  readonly sources: ReadonlyMap<string, string>;
}
```

**`Compilation.files`**

```ts
readonly files: readonly File[];
```

The parsed entry files; partial where the parser recovered.

**`Compilation.dependencies`**

```ts
readonly dependencies: readonly string[];
```

Files reached by import resolution, including missing or invalid libraries.

**`Compilation.checked`**

```ts
readonly checked: CheckedPackage;
```

Semantic facts, present even when parsing or checking reported errors.

**`Compilation.program`**

```ts
readonly program: Program | null;
```

Null unless parse, check and noding all finished without an error.

**`Compilation.sources`**

```ts
readonly sources: ReadonlyMap<string, string>;
```

Every text this run parsed, by filename: the entry files and each
library, compiler-shipped ones included. Tooling reads doc comments here.

### CompileOptions

Source capture does not change compilation or import resolution.

```ts
interface CompileOptions {
  readonly includeSources?: boolean;
}
```

## Types

### CompileResult

The outcome of [`compile`](./compiler.md#compile): the generated TypeScript module source, or the flushed, position-ordered error batch. Never both, and never a partial module.

```ts
type CompileResult =
  | {
      readonly ok: true;
      readonly source: string;
    }
  | {
      readonly ok: false;
      readonly errors: readonly ErrorMsg[];
    };
```
