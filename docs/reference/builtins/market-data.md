Values the host supplies for the current bar, available in every script without an import. Each entry says what it holds inside a request.

Price and volume of the current row, read from input columns the host supplies.

Each name reads the input column of the same name, as [`close`](./market-data.md#close)
describes. The host must supply every column a script reads, or binding the
script fails. Library files can read these names too, and no file can
redeclare or assign them.

## Price and volume

### open

Opening price of the current row.

```tea
open = input.series("open")
```

Reads the host-supplied `open` column, like [`close`](./market-data.md#close).

### high

Highest price of the current row.

```tea
high = input.series("high")
```

Reads the host-supplied `high` column, like [`close`](./market-data.md#close).

### low

Lowest price of the current row.

```tea
low = input.series("low")
```

Reads the host-supplied `low` column, like [`close`](./market-data.md#close).

### close

Closing price of the current row.

```tea
close = input.series("close")
```

Reads the `close` column of the host's input stream. A row is one item of
that stream, such as one bar, and `close` is `na` on a row where the host
supplies `NaN`. Inside a [request](../../requests.md) expression, it reads the
stream bound to that request instead.

`close[1]` is the value one row earlier and is `na` on the first row. This
computes the change from the previous row, using [`nz`](./core.md#nz) to treat the
missing first value as no change:

```tea
previous = nz(close[1], close)
emit "change" close - previous
```

### volume

Traded volume of the current row.

```tea

```

Reads the host-supplied `volume` column, like [`close`](./market-data.md#close).

### hl2

Midpoint of the current row's high and low, `(high + low) / 2`.

```tea

```

Tea does not compute it: it reads the host-supplied `hl2` column, like
[`close`](./market-data.md#close). `tea run` derives that column from `high` and `low` when the
CSV file lacks it.

## Bar and time

### bar_index

The number of the current bar, counting from 0.

```tea
series int bar_index
```

It grows by one each time a bar is finalized; repeated updates of a live bar keep the same number. Inside a request expression it counts the requested data’s bars.

### time

The current bar’s time, in milliseconds since the Unix epoch.

```tea
series int time
```

It is the `time` field of the current input row, the time at which the bar opens. Reading it requires the bound data stream to carry that field; without it, the run stops with an error. Inside a request expression it is the requested data’s bar time.

### timenow

The current clock time, in milliseconds since the Unix epoch.

```tea
series int timenow
```

The host’s clock is read once for each execution, so repeated updates of a live bar can see different values. A host may supply a fixed clock instead, for reproducible runs. Inside a request expression it is read when the requested data’s bar executes.

## Bar state

### isfirst

Whether the current bar is the first one, where [`bar_index`](./market-data.md#bar_index) is 0.

```tea
series bool barstate.isfirst
```

Inside a request expression it refers to the requested data’s first bar.

### ishistory

Whether the script is processing historical data.

```tea
series bool barstate.ishistory
```

It is always the opposite of [`barstate.isrealtime`](./market-data.md#isrealtime), including inside a request expression.

### isrealtime

Whether the script is processing live data.

```tea
series bool barstate.isrealtime
```

The host reports it for each execution. It is `false` unless the host marks the data as live, so runs over stored data report `false`. Inside a request expression it is read when the requested data’s bar executes.

### isconfirmed

Whether the current update is the bar’s final one.

```tea
series bool barstate.isconfirmed
```

It is `false` on provisional updates of a live bar and `true` on its final update. Rows that are not marked provisional are final, so historical bars are always confirmed. Inside a request expression it describes the requested data’s update. Use it to act only on completed bars.

```tea
var int completed = 0
if barstate.isconfirmed
    completed := completed + 1
emit "completed_bars" completed
```

### isnew

Whether this is the first update of the current bar.

```tea
series bool barstate.isnew
```

It is `true` for the first execution of each bar and `false` when a live bar is updated again. Historical bars run once, so they are always new. Inside a request expression it describes the requested data’s bar.
