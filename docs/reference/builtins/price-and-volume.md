Price and volume of the current bar, read from input columns the host supplies.

Each name reads the input column of the same name, as [`close`](./price-and-volume.md#close)
describes. A script computes none of them itself, not even [`hl2`](./price-and-volume.md#hl2),
[`hlc3`](./price-and-volume.md#hlc3), [`ohlc4`](./price-and-volume.md#ohlc4) and [`hlcc4`](./price-and-volume.md#hlcc4): the host supplies those too.
The host must supply every column a script reads, or binding the script
fails with an error such as "source schema does not provide series 'hl2'".
`tea run` supplies the columns of its CSV file, and computes `hl2`, `hlc3`,
`ohlc4` and `hlcc4` from `open`, `high`, `low` and `close` when the file
lacks them. Library files can read these names too, and no file can
redeclare or assign them.

**Example:** The CSV has no `hl2`, `hlc3`, `ohlc4` or `hlcc4` column, so `tea run`
computes them from the columns beside them. At index 0, `hl2` is
`(16 + 8) / 2 = 12` and `hlcc4` is `(16 + 8 + 2 * 15) / 4 = 13.5`.

```tea
emit "open" open
emit "high" high
emit "low" low
emit "close" close
emit "hl2" hl2
emit "hlc3" hlc3
emit "ohlc4" ohlc4
emit "hlcc4" hlcc4
```

```csv
time,open,high,low,close
0,9,16,8,15
1,15,18,12,12
2,12,13,7,10
```

**Output:**

```text
index  open  high  low  close  hl2  hlc3  ohlc4  hlcc4
0      9     16    8    15     12   13    12     13.5
1      15    18    12   12     15   14    14.25  13.5
2      12    13    7    10     10   10    10.5   10
```

Available in every script without an import or namespace.

| Name                | Description                                                          |
| ------------------- | -------------------------------------------------------------------- |
| [`open`](#open)     | Opening price of the current bar.                                    |
| [`high`](#high)     | Highest price of the current bar.                                    |
| [`low`](#low)       | Lowest price of the current bar.                                     |
| [`close`](#close)   | Closing price of the current bar.                                    |
| [`volume`](#volume) | Traded volume of the current bar.                                    |
| [`hl2`](#hl2)       | Median price of the current bar, `(high + low) / 2`.                 |
| [`hlc3`](#hlc3)     | Typical price of the current bar, `(high + low + close) / 3`.        |
| [`ohlc4`](#ohlc4)   | Average price of the current bar, `(open + high + low + close) / 4`. |

## Price and volume

```

### low

```

### close

Closing price of the current bar.

```tea
series float close
```

Reads the `close` column of the host's input stream. A bar is one row of
that stream, and `close` is `na` on a bar where the host supplies `NaN`,
such as an empty CSV cell in `tea run`. Inside a [request](../../requests.md)
expression, it reads the stream bound to that request instead. `close[1]`
is the close one bar earlier, `na` on the first bar.

**Example:** The close is missing at index 2, so `change` is `na` there. `previous` is
`na` at index 0, before the first bar, and at index 3, after the missing
close; [`nz`](./core.md#nz) turns a missing previous close into no change.

```tea
emit "close" close
emit "previous" close[1]
emit "change" close - nz(close[1], close)
```

```csv
time,close
0,10
1,12
2,
3,11
```

**Output:**

```text
index  close  previous  change
0      10     na        0
1      12     10        2
2      na     12        na
3      11     na        0
```

### hl2

Median price of the current bar, `(high + low) / 2`.

```tea
series float hl2
```

The script does not compute it: it reads the host-supplied `hl2` column,
like [`close`](./price-and-volume.md#close). `tea run` derives that column from `high` and `low` when
the CSV file lacks it.
